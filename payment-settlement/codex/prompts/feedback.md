# 평가자용 후속 입력 형식

## 1번 — 한 번에 한 요구사항

`[Cxx] <가장 앞선 미충족 요구사항 하나>. <재현 요청과 실제/기대 결과>. 이 항목을 만족하도록 수정하고 확인해줘.`

acceptance 표의 P0→P1, 같은 우선순위는 ID 오름차순. 서로 다른 문제를 하나의 문장으로 묶지 않는다. 이전 통과 항목의 회귀도 같은 순서로 처리한다. evaluator 결과 원문은 보존하되 다음 항목의 해법/정답 목록을 노출하지 않는다.

## 2번 — 구조화된 수정 프롬프트

`목표: 동결 계약 충족. 미충족 항목: [ID별 요구/재현/실제/기대]. 제약: 공통 한도 유지. 검증: 관련 회귀 테스트와 이전 통과 항목 재검증. 완료 보고: 수행한 검증과 남은 실패.`

판정기가 확인한 실패를 모두 전달하고 구현 해법은 주입하지 않는다. 피드백을 LLM으로 작성하면 그 토큰도 prompt-author 역할로 집계한다.

## 3번

동일 판정 결과를 PM에 전달한다. PM이 하네스 log/리뷰 ledger와 연결해 후속 워커를 통제한다. 대리 사용자 응답은 answer-policy.md에만 따른다.
